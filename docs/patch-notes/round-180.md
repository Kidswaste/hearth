# Round 180: game projects, a playtest in the window you choose, and saves that last
*November 2026*

## 🎮 A game is now a kind of project
- **＋ New project › Start from › 🎮 Game** makes a project that begins as a small playable game: you move, jump and
  collect coins, with the score and your best kept between sessions. It is there to be changed into your own game.
- **An existing project can become a game project**: open its menu (the project's name ▾, or ⋯ on its card) and
  click **Game project** under Settings. Click it again to turn it off. Only the mark changes; nothing in the
  project is touched. Do this once for Ascend to Heaven and Clink.
- In a game project the Lab's ▶ Play button reads **▶ Playtest**, with **💾 Saves** next to it. Everything else in
  the Lab stays where it was.
- The project's AI finds out it is building a game the first time it looks at the scene, and has a guide for the new
  game tools below. Nothing was added to what it reads on every message.

## ▶ Playtest: your new-format games run, where you choose
- **New-format (v2) scenes now play in ▶ Play.** Before, the window opened and stayed black without a word. Ascend
  to Heaven is a v2 scene, so this is what makes it playable there.
- **Play in** (right-click ▶ Play): **Full screen**, or a **window** of 1280 × 720 or 1920 × 1080. The window opens
  in the middle of the screen picked under **Play on**, has a normal title bar and can be resized.
- **F5** starts the game again from the beginning, with your code as it is now. **F6** pauses and resumes. **F7**
  moves one frame forward while paused.
- As before: **Ctrl+P** goes back to editing with the game kept, your edits go into the running game, and an error
  shows as one line over the game with "Fix with the director".

## 🖱 The mouse and keyboard belong to the game
- Left, right and middle click, the wheel and every key go to the game. A right-click never opens a menu.
- In a v2 game the mouse is no longer grabbed on the first click. A game that wants to capture the mouse (a
  first-person camera) asks for it itself; a game played with the pointer (units, menus, a map) keeps its pointer.
- In a v2 game the frame-rate chip moved from **F** to **F3**, so F is free for the game.
- The way out is the same and always works: **Esc** shows "Back to Hearth", **Esc** again leaves.
- Games get a ready-made **input** tool: which keys and mouse buttons are held or were just pressed, mouse movement,
  the wheel and gamepads, plus a steady 60-times-a-second step for the game's rules, so a game plays the same on a
  60 Hz and a 240 Hz screen.

## 💾 Saves that survive
- Games get a **save** tool: named save slots, plus small settings such as a best score or the volume.
- Hearth keeps them on this computer, one folder per game. They survive closing the game, restarting it and
  restarting Hearth, and the Lab preview and ▶ Play see the same saves.
- **Saves** (right-click ▶ Play, or 💾 Saves in a game project) lists each save with its date. From there you can
  **playtest from a save**, **delete** one, **clear them all**, or open the folder. Deleted saves go to the Recycle
  Bin, so a mistake can be undone.

## What is not done yet
- **Your existing games are not changed.** Ascend to Heaven still saves its best tier the old way, which does not
  last. Ask its AI to "switch the saves to the new save tool" (a few lines) and it will.
- **Clinky** (old format) plays as before. It gets the window mode, F5 / F6 / F7 and the Saves list, but the new
  input and save tools are for v2 scenes only.
- **In the Lab preview, keys still do not reach a game** while PLAYER is on SEPARATE (the round 178 limit). Use
  ▶ Playtest to play, or switch PLAYER to IN-APP.
- Saves stay on this PC; they are not synced to your other computers.
- Not tried on a real second screen, with a real gamepad, or on the Mac.
