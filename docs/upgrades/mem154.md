# Round 154 (ships as round 156) · mem154: Hearth gives memory back

The owner: "work on trimming and making things lighter". This round lowers memory and process count **without removing
a feature**; feature switches (Trim Hearth) and Lite mode are other rounds.

## How it was measured

- **`dev/mem154-measure.js`** (a smoke.js script, not a check): `node dev/smoke.js --fake-engines --check-timeout
  1000000 --script dev/mem154-measure.js [--eval "localStorage.setItem('lab.restMs','20000'); window.MEM_AWAY=40000;
  window.MEM_LW_WAIT=40000"]`. Per setup: every process' working set (`app.getAppMetrics`), private and proportional
  memory (Linux `/proc/<pid>/smaps_rollup`; `powerwisemain.js` metrics `{ mem: true }`, tests only), the process count,
  each page's JS heap after a GC (CDP `Runtime.getHeapUsage`) and the main process' heap.
- Setups: a project chat open, idle (70 s after the start) · the Lab playing realscene-lib's heavy scene at 960 × 540 ·
  back in the chat right after · back in the chat past the Lab's rest time · the Lab window with Hearth hidden, playing.
- This box: 4 shared CPUs, software GL (the GPU process is SwiftShader), Linux. Working set counts shared pages in every
  process, so the totals are higher than what the system really spends (PSS column).

## What changed

1. **The Lab rests when unseen** (`tools/three.js`, `restArm / restTry`, `ThreeLab.rest`): out of view (a chat, another
   tool, Hearth hidden or minimised) for **5 minutes** with nothing going on, the preview page is let go through the same
   path as leaving for Projects (`workspace.close()`: code and slider edits saved, the song's place remembered; the page,
   its WebGL contexts, decoded textures and sound go). Showing the Lab runs it again (`onShow → workspace.resume()`); an
   AI call on the scene wakes it first (`handleVisible → ThreeLab.rest.wake()`, waits for the page's `ready`). Never
   while: the song / timeline plays, recording, rendering, live sound, the Stage window, ▶ Play or a baked show, a
   project opening, an AI turn on that scene, the Lab window holding it. A busy moment restarts the quiet time. Shown
   while being let go: it comes straight back. Tests: `localStorage 'lab.restMs'` (ms, `0` = never).
2. **A hidden window trims** (`memtrimmain.js`, new; `preload.js`): Hearth's window (and the Lab window) hidden or
   minimised for 30 s → its preload runs `webFrame.clearCache()` (Blink's caches emptied, a full GC under memory
   pressure) and fires `hearth:mem-trim` for the page. Once per time out of sight; nothing while shown; the page can't
   call it. Covers the tray and "Hide Hearth while the Lab window is open". `HEARTH_TRIM_MS` for tests.
3. **The warm preview page** (`tools/three-boot.js`) and the hidden Lab mounted for a likely project are let go after
   **5 minutes** unused instead of 15 (≈ 250 MB: a renderer plus its GPU memory, on every start of someone who uses the Lab).

## Looked at, not changed

- **The audio service (≈ 70 MB) stays after the last sound stops.** Chromium keeps it alive for the app's life; tried
  `audio-service-quit-timeout-ms` in a bare Electron 44 app: it still never quit. Left alone.
- **The GPU process stays ~60 MB above its start after the Lab** (compiled-program cache, 32 MB cap set for ▶ Play in
  round 52; driver allocations). No safe way to purge it from Electron.
- **Chromium switches** (`disable-features` for MediaRouter / Translate / BackForwardCache / autofill): Electron already
  ships without most of these; nothing to win worth the risk. Spellcheck is used (the right-click "Add to dictionary"),
  `<webview>` is used by website agents and app windows, so both stay. No `js-flags` heap tuning: the heaps are 9–15 MB.
- `renderer-process-limit` / no site isolation would merge the preview into Hearth's window: the scene's JavaScript
  would then share the window's thread (the lag this app fought for 100 rounds). Not done.
- Main process: already loads ~40 modules on first use (`lazyIpc`, `later()`); its JS heap is 11–13 MB.
- The backstage page already lets go after 60 s idle; the Stage window is destroyed when closed.
