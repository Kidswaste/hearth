## 2. labdrop61: a .glb dropped on a project's chat wasn't added to the scene's references

**Root cause.** Report #61's fix (a project chat handles drops like the director: `native.js` `labChat` → the Lab's
`addReference`) was later undercut by round 72 (labbridge72): `labReference` refuses a chat that has no scene link
unless the agent's dock is `'three'` ("This chat isn't linked to a Lab scene yet", so a plain unlinked chat keeps the
file as an attachment). A project's chat is not a docked director (its turns get `dock: 'three'` only per turn, through
`engines.js` `asDirector`), and isn't linked to a scene until the AI first works on it — so every drop threw, fell to the
"Lab can't take it" branch and became a copy in the attachments folder. The check's middle step (`addReference` called
once with the .glb) failed; the other two passed. (The git history here starts at one squashed import, so the exact
round can't be bisected; the rule and the comment date it to round 72.)

**Fix** (`native.js`): `projectLab(agentId)` (the same test `labChat` used) also lets `labReference` go on without a
link, as the director's dock does: the file goes to the open sketch's references (`ThreeLab.addReference(path)`), with
the "reference: …" note. A plain chat without a link is unchanged (it keeps the attachment), and a linked chat still
goes to its own scene.

## 3. Hearth's window lets its Lab go while the Lab window holds the scene

### What it does

`ThreeLab.drop()` (`tools/three.js`), called by `LabWinHost.open` once the Lab window is up:

1. **mem154's rest path**: `workspace.close()` — the code and slider edits saved, the song's place remembered, the
   preview page released (its process, WebGL contexts, decoded textures, sound).
2. **`api.teardown()`** inside the sketch tab: everything the tab hooked outside its own DOM. Its bare
   `addEventListener` / `setInterval` / `setTimeout` / `MutationObserver` / `IntersectionObserver` / `ResizeObserver`
   names are the tab's own (one `AbortController`, tracked timers and observers), document listeners go through
   `docOn`, its chat hooks through `life.hook`, its StoreAck holders through a wrapped `SA.hold`, plus: the battery
   listener, the preview-reload hook, Power's `lab-media` / `lab-stall`, the parts' timers, the body-level key hint and
   focus-exit button, the sandbox page (`box.dispose()`: its window `message` listener, crash check, the grade panel's
   page) and the timeline player (`player.dispose()`: its window listeners, timers, sound contexts, LabPlay's tick hooks,
   its beat-grid holder).
3. **The DOM and api**: the tab strip and the surface's body emptied, `tabs = null`, every `api.*` deleted, the module's
   caches (code editors, sandbox libs) cleared. Other modules' own chips (Direction, Finish, Lab search, frame budget,
   project look, footage chip, live light, sequence view) leave the tree first.
4. **`hearth:lab-drop`**: the Lab's feature modules go back to their "before the Lab mounted" state (`lab = null`,
   `h = null`, `host = null`…): three-music, -audio, -motion-in, -frames, -seq, -comp, -models, -gestures, -camera,
   -direct, -materials-hook, -nodes (its window key and probe), -shader (its lens), -regroup (folds, timeline header),
   -hudstage (its preview HUD; its window-wide listeners now once per window), -boot (the preview size watcher) and
   chat-scenes' sketch picker.

Proof that nothing keeps the tab: `dev/fix161-leak.js` (a heap snapshot after the drop) found the holders one by one
(hub.onNowPlaying's subscriber made inside the tab, LabPlay's tick hooks, StoreAck holders, the shader lens, the
sequence strip's buttons, a script tag's onload, a pending timeout, the mount's key listener on the surface…) until a
`WeakRef` to the tab's director comes back empty after a GC.

### While it is dropped

- The surface stays "mounted" and shows only the Lab window's card ("Open in Lab window ↗ · Bring it back here");
  showing the Lab there builds nothing.
- **The director's calls**: `LabWinHost.route` reads the chat's link alone (`ChatScenes.linkOf`, no Lab needed): a chat
  linked to the away scene, or a call without a chat, goes to the Lab window as before; any other chat's call runs here
  (`handleTool` mounts a Lab again first, then routes as always: backstage for another scene).
- **Anything else that needs Hearth's Lab** (`ThreeLab.cmd`, a code block, a Lab action, the nodes commands) mounts a new
  one (`ensureMounted`), as on the Lab's first open: it reads the scenes from disk, the away scene stays held (card, no
  preview). `ThreeLab.drop()` can let it go again.
- Chats, drafts, streaming replies, the drawer's messages (`labwin:ask` → `Native.send`) and their replies back to the
  drawer don't touch the Lab and carry on. The docked chat lives in the surface's dock, not its body: untouched.

### Coming back

The Lab window closes → `LabWinHost.closed` → `ThreeLab.cmd({ show: true, sketch: id })`: a new mount on that scene,
read from disk with everything changed in the Lab window, its preview running again. A second open / close cycle drops
and restores again (the check).

## 4. lite153's persist flake (asked during the round)

"persist: after a reload Lite is on before the first frame" failed once in a combined run with `{ dcl: true, frame:
false }`. **A real race, not the probe**: `data-lite` was set only by `powerwise.js`, a `defer` script, which runs after
the whole page is parsed, just before DOMContentLoaded; Chromium may run animation frames (and paint) before deferred
scripts once the render-blocking stylesheets are in, and round 159 (fewer, smaller sheets) makes that likelier. The
probe's `requestAnimationFrame` then saw no `data-lite`: those first frames had the animations and glow Lite removes.
**Fix**: `lite-early.js`, one parser-blocking line at the top of `<head>` (the CSP allows no inline script) in
`index.html` and `lab-window.html`, sets `data-lite` from `localStorage hub.lite` before anything can paint;
powerwise.js keeps owning the switch. It is not a deferred script, so the first-screen budget (`unit:boot-test`) is
unchanged.
