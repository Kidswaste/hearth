# a11y (round 40): Hearth with the keyboard, VoiceOver and Narrator

Hearth now works with the keyboard alone and tells a screen reader what each control is, on the Mac and on Windows.
Nothing looks different with a mouse. Every Tab stop shows a ring, Esc closes whatever is on top and puts you back
where you were, and the arrow keys move through menus, lists and pickers. VoiceOver and Narrator now read "Mission
for your next message" where they used to read "◎", and they read a finished reply once instead of every word as it
streams in. It also holds up in Windows High Contrast and with "Increase contrast" on.

Most of the work is in one small new file, `a11y.js`, which loads early and fills in what other parts of the app leave
out. The rest is `a11y.css` plus a few one-line hooks in other files (listed at the end).

## What shipped

### Keyboard
1. **Skip to the chat**: the first Tab stop. It is only visible while focused, and Enter puts you in the chat box of
   the window you're in.
2. **A focus ring on every control, in every look** (31 looks). It shows when you use the keyboard, never on a mouse
   click, and turns Highlight in Windows High Contrast.
3. **Esc closes the top-most thing**: a menu, then the picker, AI setup or dialog under it. It also works when focus
   was still on the button that opened it. A menu over Settings closes first, then Settings.
4. **Focus goes back to where it was** after AI setup, ◎ missions, Find anything, the Lab's ✦ picker, Lab search, the
   menus and any dialog close (for example, Find anything gives focus back to the chat box).
5. **Focus goes into what opens**: AI setup, ◎ missions and the Lab's pickers take focus. Opened from the keyboard,
   focus lands on their first button, so Tab doesn't wander off behind them.
6. **Menus opened from the keyboard** (Enter on a ⋯ button, Shift+F10, the menu key) start on their first row. ↑ / ↓
   / Home / End and letters move a real focus that screen readers follow. Tab closes the menu and carries on from the
   button that opened it. With the mouse, menus behave as before.
7. **The Lab's own menus** (sliders ⋯, layer and toolbar pop-ups) work the same way: first row when opened by
   keyboard, real focus, focus back on close.
8. **The chats list is one Tab stop**: ↑ / ↓ / Home / End move between chats, Enter or Space opens one, F2 / Delete /
   Shift+F10 work as before.
9. **The keys sheet** (keys button, bottom left) has a new "Keyboard" part listing these.

### Screen readers (VoiceOver on the Mac, Narrator on Windows)
10. **Icon-only buttons have names** taken from the first part of their tooltip: "Home", "AI setup", "More", "Tokens
    today: 0", "Mission for your next message", "Attach", "Close", "Look again", the Lab's 🔎 / ⋯ / 📷 / 4:5 / 👁 / ★ /
    🎲 / ✦ / ◇ / ♪ buttons, and more. The full tooltip is still read as the description. A name follows its tooltip
    when the tooltip changes and is dropped when the button gets real words (◎ → "🎯 Debate").
11. **◎ Missions**: each 📌 is read as "Debate: from now on" (the mission it belongs to), and the picked mission is
    read as pressed.
12. **Find anything (Ctrl/⌘+K)** is a search box over a list of results: ↑ / ↓ reads the highlighted row, and the
    row is read as selected.
13. **🔎 Lab search** rows say which one is selected.
14. **Lab knobs are sliders** to screen readers: name, lowest and highest value, and the current value as you turn
    (arrow keys already turned them). The number under a knob reads "Type a value for Glow".
15. **Lab sliders, number boxes, color pickers and hex boxes are named after their control** ("Glow", "Glow, exact
    value", "Tint color, hex"). A literal with no name reads as "Value 0.4, line 12" instead of "0.4".
16. **Lab On/Off pills are switches** with their state, and a choice's buttons say which one is picked.
17. **Finished replies are read out once, politely**: "Claude replied: …" with the start of the reply (code blocks
    read as "(code)"). An error or a stop is read out too. Nothing is read while it streams: the check counts 2
    changes for a whole long reply.
18. **Notifications (toasts)** are read out politely.
19. **Tips** from Hints are read out politely, both the calm optional ones and the essential notes.
20. **The rail ("Apps and tools"), the chats panel ("Chats"), AI setup, ◎ missions and Find anything are named**
    regions and dialogs, so a screen reader can jump to them. A chat row is a button, and the open chat is marked as
    current.

### Contrast and the computer's display settings
21. **Light looks (Forge Light, Chrome Light, Parchment, Frost Light, Light):** the current AI's name in the chats
    list is now readable (2.58–4.16:1 → at least 4.5:1).
22. **Light looks:** the "Message Claude…" and "Search chats" placeholders now meet 3:1 (they were 2.76–2.94:1).
23. **Windows High Contrast / contrast themes:** every button keeps an edge, stroke icons follow the text color
    (some looks tinted them with a fixed color that High Contrast doesn't change), anything on or picked keeps a
    Highlight mark, and focus shows in Highlight. Pictures, video and the Lab preview keep their real colors.
24. **"Increase contrast" (Mac) / contrast themes (Windows) → `prefers-contrast: more`:** muted text, hints,
    placeholders, menu key hints and lines get stronger.

Reduced motion was checked, not changed: with the OS setting on, opening AI setup moves nothing, and motionpolish
covers the rest.

## How it works (for the next stream)
- `a11y.js` (`A11y`, also `window.A11y`) is loaded right after `hints.js` and starts at DOMContentLoaded.
  - Names: one MutationObserver on the page (added nodes + `title` / `aria-label` changes) feeds one idle pass. A
    control whose own text has no word gets `aria-label` = `A11y.shortName(title)`, marked `data-a11y-name` so it can
    be updated or removed later. A name set by its own module is never touched.
  - Overlays: a second observer watches only `<body>`'s own children for `aside.opt-sheet`, `.ms-pop`, `.palette`,
    `.fx-picker` and any `[role=dialog]`. When one appears it is recorded with its opener, focus moves in (a task, not
    a frame, so a busy Lab can't delay it), and it gets the dialog role if it had none. When it is removed, focus goes
    back to the opener if focus was lost. `<dialog>` closes are caught in the capture phase. Esc that nothing else
    handled closes the top-most overlay (its ✕ / Close button, `Options.hide()` for AI setup).
  - `A11y.say(text)`: the one polite live region (`#a11y-live`). `A11y.kbd()`: true if the last input was the keyboard.
- Menus: `renderer.js` `showMenu` remembers the opener (`menuState.opener`; a submenu keeps it). `menuKb` focuses the
  row, or sets `aria-activedescendant` while you type in the filter. `hideMenu` gives focus back. Tab closes. `popMenu`
  does the same.
- New UI: give an icon-only button a `title` (it becomes the name) or an `aria-label`. Put pop-ups on `<body>` with
  `role="dialog"` and an `aria-label`. Use `A11y.say()` for things that should be heard. The focus ring comes from
  `a11y.css`; don't use `outline: none !important` on controls.

## Tests
- `dev/checks/a11y.js` (new; `sh dev/run-checks.sh a11y` runs it plus the checks below). It walks real key presses
  over CDP, emulates forced-colors and reduced motion over CDP, and runs a fake streamed reply through the fake engines.
  `window.A11Y_ONLY = [...]` runs some parts only; `window.A11Y_DEBUG` lists the page's capture key listeners.
- `sh dev/run-checks.sh a11y`: 13 of 14 pass (a11y with 0 problems; options, settingscalm, appsearch, missions,
  missions2, swarmlean, labeasy, labsearch, motionpolish, lazy, unit:boot-test, unit:swarmlean-test).
- qa-keys fails on round 39's `main` as well, with the same flaky keys dead from run to run. Run 4 times on each side,
  limited to Everywhere and Capture, both show the same set: Ctrl+\, Ctrl+B, Ctrl+Alt+P (capture's indicator page
  can't load here), plus the Lab's "|". labsearch failed once on a timed row flash and passed when run again.
- The before numbers come from the same check run on a31bfd9 (the check works without `A11y` in the page).
- `node --check` on every JS file touched.
- Not tested: real VoiceOver / Narrator and real Windows High Contrast. High Contrast is emulated (Chromium's
  forced-colors), and the screen reader parts are checked through roles, names and live regions, not with a speaking
  screen reader.
