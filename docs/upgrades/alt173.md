## 1. Alt: the tucked controls are marked while shown

declutter.js wrote two rules per tucked selector: `:root:not(.reveal-alt) <x> { display: none }` and `.reveal-alt <x>
{ outline, dc-reveal }`, plus `:root:not(.reveal-alt) <host>:not(:hover) <x>` for the 'hover' ones. Toggling
`.reveal-alt` on `<html>` invalidates, for each such rule, every element matching `<x>`'s last part, and those last parts
were `button` (`.notes-foot > button:nth-of-type(n)`, `.native-head > button:last-of-type`, Forgeheart's
`.tabbar > button:nth-child(n+6)`, `button[title^=…]`), `[title]`, `[data-feature]`, `.ghost`, and polish8's
`.bdd-foot > span`: every button, span and titled element of the page, twice per hold.

*Fix* (declutter.js `paint` / `syncReveal` / `remark`):
- Hidden is plain CSS that no longer mentions `.reveal-alt`: `:root <x>:not(.alt-reveal) { display: none !important }`
  (the same specificity as before: `:root` + one class).
- While `.reveal-alt` is on (Alt held, a double-tap latch, `/reveal`), exactly the elements matching the tucked selectors
  (one `querySelectorAll` of them, keep states included) carry `.alt-reveal`; the outline and the reveal animation are
  one rule, `.reveal-alt .alt-reveal`. 'Hover' rules whose last part names no class or id (polish8's `.bdd-foot > span`,
  the memory rows' `button[title^="Set an expiry"]`) work the same way with `.alt-hover` (no outline, as before); those
  that end in a class keep their `:root:not(.reveal-alt)` form (they reach only that class).
- Marked lazily, not kept up all the time: a MutationObserver on `<html>`'s class sees `.reveal-alt` come and go (same
  microtask, before the frame) and marks / unmarks. While shown, a second observer (body subtree: children, class,
  title, data-feature, id) re-marks in the next animation frame, so anything arriving or changing while Alt is held or
  latched is shown in its first frame. While Alt is up nothing is marked and nothing is watched, so no app-wide
  observer runs in normal use (a mark kept up all the time would need one on every class change of the page).
- A selector the browser can't parse (a hand-tucked one) is dropped from the list, as it would have been ignored.

Ctrl's key badges are unchanged (they read what is visible, as before). Same visible behaviour: the rail's tucked button
shows with the dashed gold outline while Alt is held and goes with it (now asserted in restyle172), the latch and Esc
work (declutter's check), and a screenshot with Alt held shows the same outlined buttons (rail ＋, ⌕, ⛶, the board drawer
peek, ⚇ on the composer) and the hover controls (NATIVE, ＋ on group heads).

## 2. The chats list: `.row-far` instead of `:nth-child(n+14)`

chatcore.css let a long group's rows past the first dozen skip layout and paint (`content-visibility: auto`) with
`#chat-groups .group > .item:not(.active):nth-child(n+14)`. A position rule marks the group "children affected by
position", so each row added or removed restyled every row after it.

*Fix:* panel.js' `farMark` puts `.row-far` on each `.item` from the group's 14th child on (the same rows); called at the
end of `patch()` and by a MutationObserver per group (`farWatch`, made with the group) for anything else that adds or
removes children. Only a row crossing the line changes class. chatcore.css: `#chat-groups .group > .item.row-far:not(.active)`.
