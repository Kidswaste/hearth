# Project switching, Clink loading, and project identities

Clink's live PC baseline was 10.5 seconds to open, with a 7.7-second main-thread task. CPU profiling identified construction of controls for every layer as the largest cost. Its 56 layers contain over 36,000 tweakable values. Controllers still prepare the complete values, keyframes, music bindings and director API; only the selected layer builds its controls. Raw code values are paged, and searching includes values outside the current page. Hidden previews also park controller motion timers.

Project switches move the existing chat view without refreshing its history. A full-width Chat tab stays in the project. Creative Board remembers its last station, reuses its canvas and controls on return, and suspends playback/polling while hidden. Closing a project still flushes data and releases its preview and sound host. Related project conversations can be opened inside the workspace, preserving their own drafts and scene links.

Each project has a Three.js banner/logo editor, reached from the star on its card, its menu, or its overview. Start with brushes, blocks, a ship, an orbit, a crystal or a waveform; describe an identity to generate an AI composition; preview, adjust and save it. Generation uses the existing native AI helper and a validated, bounded composition, with no generated executable code. Rendering runs in an OffscreenCanvas worker. Cards use saved PNG posters when idle; only one project identity animates at a time, stopping when hidden or closed and respecting reduced motion. Image data lives in a separate per-project store, not the shared projects index.

Projects > More > Bring Three.js chats into Projects groups existing chat/scene references without rewriting either content. Missing/deleted sources and orphaned generated project chats are skipped. Repeating the import is safe. Related work can be attached to an existing project before importing the remaining chats.

Validation: project metadata/import bounds; 12 project model tests; 13 workbench tests; boot budget and lazy-manifest parity; real Electron project switching/drawing retention, full-width chat and draft retention, raw-value search, banner preview/save/poster, related chat navigation, project/reload isolation, and save-failure/cancel lifecycle coverage. The actual Clink scene was also exercised in an isolated Electron fixture. Final live timings are recorded in the delivery report. Physical macOS and audio-interface testing require those devices.

The broader beat-link journey exercises music binding, live input, undo, scene switching, rendering and export. Its strict every-sample playhead comparison fails both on the unchanged live installation and on this branch under the Windows smoke harness; this is recorded separately from the passing project checks, not counted as a clean pass.
